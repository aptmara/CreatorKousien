# コード・アセット命名・配置ガイドライン (CreatorKousien)

本プロジェクトの設計思想に基づき、ファイルとクラスの命名および配置に関するルールを定めます。

---

## 1. ファイル・ディレクトリ構成

アセットの種類に関わらず、**[ドメイン]** 単位でディレクトリを分割します。

### 基本構造
- `Assets/Scripts/[Domain]/` : スクリプト
- `Assets/Prefabs/[Domain]/` : プレハブ
- `Assets/Data/` : ScriptableObject（定義データ）

---

## 2. スクリプト命名規則

クラス名とファイル名は一致させ、役割を示す **接尾辞 (Suffix)** を必ず付与します。

### 接尾辞と役割
| 接尾辞 | 役割 | 継承元 |
| :--- | :--- | :--- |
| **Data** | 静的な定義データ | `ScriptableObject` |
| **RuntimeData** | 実行時の状態保持 | `Pure C#` |
| **Service / System** | ロジック・計算・API | `Pure C#` |
| **View / UI** | 表示・演出・入力受付 | `MonoBehaviour` |
| **Command / Result** | 処理要求と結果のデータ型 | `Pure C#` |

### 具体的な例
- `FieldService.cs` : フィールドロジック
- `PlayerRuntimeData.cs` : プレイヤーの状態
- `CardView.cs` : カードの見た目制御

---

## 3. コードスタイル規則 (`.editorconfig` 準拠)

- **クラス・メソッド・プロパティ**: `PascalCase`
- **プライベート変数**: `_camelCase`（アンダースコア始まり）
- **列挙型（Enum）**: `PascalCase`

---

## 4. 設計を守るための遵守事項

レビュー時に特にチェックされる項目です。

1. **View からの直接書き換え禁止**
   - `View` クラスは `RuntimeData` の値を参照（Read）して表示を更新するのみとし、値を直接書き換えてはいけません。
2. **所有権の尊重**
   - データを書き換えてよいのは、そのデータの **所有システム (Owner)** のみです。
   - 他のシステムから値を変更したい場合は、必ず対象の `Service` クラスのメソッドを介して行ってください。
3. **メタファイルの整合性**
   - 新規ファイルの追加時は必ず `.meta` ファイルを含めてコミットしてください。
   - GitHub Actions で自動チェックされます。
