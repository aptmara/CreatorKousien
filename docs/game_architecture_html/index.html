ガバっと一掃！ プロトタイプ設計HTML

本資料は、ゲーム企画「ガバっと一掃！」を、個人プロト・統合・全体プロト調整の順に実装できる粒度へ落とし込んだ設計資料である。目的は、複数人が同時に作業しても破綻しにくい構造を先に決め、後からメカニクス・演出・ステージ・敵・データを拡張できる状態でプロトタイプを成立させること。

結論。 本プロトタイプは Unity + C#、GameObject/Component中心、ScriptableObjectデータ駆動、イベント通知、Prefab契約、Additive Scene構成で進める。物理挙動は完全シミュレーションに寄せず、収集中は軽量なバッファ管理、解放時だけ演出用Rigidbodyを使うハイブリッド方式にする。

プロトタイプの到達目標

観点到達目標採用基準
コア体験大量に集める、溜める、一気に落として敵に当てる流れが30秒以内に理解できる。初見プレイヤーが説明なしで「集めて落とす」を認識できる。
爽快感解放時にヒット数、敵リアクション、画面揺れ、効果音、物量で結果が明確に出る。少量解放と大量解放の差が見た目・音・数値で明確。
判断敵ゲージ、バリア、物の種類、落とす位置により「どう集めるか」が発生する。単純に全回収するだけより、狙って集めた方が良い結果になる。
並列実装各担当が自分の検証シーンで完結して作業し、統合時は契約済みPrefab/APIのみ接続する。共有シーンの同時編集を避け、Prefab単位でPR/マージできる。
拡張性敵、物、合体、ステージギミック、ボス条件をScriptableObjectやPrefab差し替えで追加できる。新しい敵・物を追加するとき既存コード改修が最小。

開発フェーズ

Phase 1: 個人プロト

各担当が独立検証シーンで、操作・収集・落下攻撃・敵ゲージ・崩落・合体・UIなどを個別に作る。統合前提のInterface、Event、Prefab契約だけ共有する。

Phase 2: 統合

個別プロトをGameplayShell + Stage_Prototype_01へ接続する。見た目よりも、入力から敵ダウンまでの一連のゲームループ成立を優先する。

Phase 3: 全体プロト調整

操作感、物量、パフォーマンス、ゲージ速度、ナダレ演出、難易度、視認性を調整する。体験が薄い箇所を削るか、判断要素として強化する。

本資料の前提

  • 使用言語はC#、実装環境はUnityを想定する。
  • プロトタイプ段階では、完全なローグライク生成、恒久的なセーブ、製品版UI、細かい育成要素は作らない。
  • 大量物体は全てを常時物理演算しない。収集中はデータ化し、解放・演出時のみ物理表現を使う。
  • 担当者は実名ではなく、実装者A〜Hとして粒度を定義する。チーム人数に合わせて統合・分割できる。
