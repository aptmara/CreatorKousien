04 Parallel Implementation

実装人物粒度・並列作業設計

個人プロトの段階では、各担当が独立して検証を進める。統合時の破綻を防ぐため、各担当の成果物、編集範囲、完了条件、依存先、渡すデータを細かく定義する。

担当分割の全体像

担当カテゴリ目的主な成果物統合時の接続先
実装者Aプレイヤー操作・収集「動いて集める」手触りを作る。PlayerPrototype、CollectionBuffer、ArmSweepController。ReleaseController、HUD。
実装者B解放・落下攻撃・ヒット「集めた物を落として当てる」結果を作る。ReleaseEmitter、DropTrajectoryResolver、HitBatchAccumulator。CollectionBuffer、EnemyController。
実装者C敵・攻撃ゲージ・バリア敵の攻撃予兆、ダウン、本体ダメージを作る。EnemyPrototype、EnemyAttackGauge、BarrierController。HitBatch、StageTiltController。
実装者D収集物・合体・形状変化「どう集めるか」に意味を持たせる。CollectableDefinition、FusionRecipe、PayloadMutationSystem。CollectionBuffer、DamageResolver。
実装者Eステージ崩落・雪崩敵撃破が次の大量ダメージへ連鎖する構造を作る。StageTiltController、AvalancheFlow。EnemyDefeatedEvent、HitBatch。
実装者Fボスステージギミック通常ステージと違う最終局面を作る。BossStageGimmick、FieldWeightSystem、BossTimerRule。StageController、RunRuleController。
実装者GUI・演出・フィードバック収集量、解放結果、敵状態を分かりやすく見せる。HUD、GaugeView、HitPopup、CameraFeedback。EventBus。
実装者H統合基盤・デバッグ・ビルド全員の成果物を接続できる器を用意する。Boot、GameplayShell、PoolService、DebugOverlay、チェックリスト。全モジュール。

実装者A: プレイヤー操作・収集

目的

プレイヤーがステージ上を移動し、周囲の物をガバっと巻き込む感覚を作る。ここが弱いとゲーム全体の印象が薄くなるため、数値よりも操作感と視覚変化を優先して検証する。

作業単位内容成果物完了条件
A-01 入力読み取り左スティック移動、任意で右スティック解放方向を取得する。PlayerInputReader.csDebug表示で入力ベクトルが確認できる。
A-02 移動見下ろし視点での移動、加速、減速、回転を実装する。PlayerMotor.cs狙った方向へ違和感なく移動できる。
A-03 腕スイープ範囲左右または前方の収集範囲をColliderで表現する。ArmSweepController.csGizmoで収集範囲が見える。
A-04 収集判定範囲内のCollectableEntityをCollectionBufferへ入れる。PlayerCollector.cs物を拾うとField上から消え、保持数が増える。
A-05 保持Visual保持数に応じてプレイヤー周囲に物のVisualを表示する。CollectedPayloadVisual.cs保持量の増加が見た目で分かる。
A-06 容量・重さ影響保持数、重量、速度低下を仮実装する。CollectionCapacity.cs大量保持時のメリット/デメリットを調整できる。
A担当の統合契約。 外部へ公開するのは IReleasablePayloadSource と CollectionChangedEvent。Release側はCollectionBuffer内部を直接触らない。

実装者B: 解放・落下攻撃・ヒット

作業単位内容成果物完了条件
B-01 解放入力ReleaseRequestを作成し、CollectionBufferからPayloadBatchを取得する。ReleaseController.csボタン入力で保持物が減る。
B-02 DropZone判定解放方向・プレイヤー位置から落下先を決める。DropZoneResolver.cs左右/前方の敵に狙って落とせる。
B-03 落下演出生成PayloadBatchから演出用ProjectileをPool生成する。ReleaseEmitter.cs1個/10個/50個で見た目の密度が変わる。
B-04 命中判定ReleasedPayloadProjectileが敵のHitAreaへ当たる。ReleasedPayloadProjectile.cs敵へHitResultが送られる。
B-05 HitBatch集計短時間に当たったヒットを束ねる。HitBatchAccumulator.cs大量ヒット時に1つのBatchとして扱える。
B-06 ダメージ計算Payload属性、量、速度、敵状態からダメージを出す。DamageResolver.cs少量/大量/属性ありで結果差が出る。
B担当の統合契約。 入力は PayloadBatch、出力は HitBatch。Enemyの内部ゲージ値を直接操作しない。

実装者C: 敵・攻撃ゲージ・バリア

作業単位内容成果物完了条件
C-01 EnemyFacade敵全体の窓口を作る。EnemyController.csApplyHitBatchで外部から攻撃できる。
C-02 攻撃ゲージ時間で増加し、HitBatchで減少し、満タンで攻撃する。EnemyAttackGauge.csゲージの増減がDebug表示される。
C-03 ダウンゲージ0でダウンし、一定時間本体へダメージ可能にする。EnemyDownState.csダウン中だけHPが減る。
C-04 バリアダメージ無効範囲、属性無効、特定Payloadで解除を実装する。BarrierController.cs無効/有効の差が見える。
C-05 敵攻撃ゲージ満タンでプレイヤーへダメージ。EnemyAttackExecutor.cs放置するとプレイヤーが負ける。
C-06 撃破通知HP0でEnemyDefeatedEventを発行する。EnemyDefeatHandler.csStage側が撃破を検知できる。
C担当の統合契約。 敵は IDamageableByPayload を実装する。Stage側はEnemyControllerを生成・登録するが、Gauge内部は触らない。

実装者D: 収集物・合体・形状変化

作業単位内容成果物完了条件
D-01 収集物定義CollectableDefinitionを作る。SO_Collectable_*群3種類以上の物を作成できる。
D-02 スポーンSpawnZoneから物を出す。CollectableSpawnSystem.cs一定数まで自動補充される。
D-03 Payload化拾われた物をPayloadへ変換する。PayloadFactory.csFieldPrefabとPayloadの対応が取れる。
D-04 合体判定特定組み合わせで新Payloadへ変換する。FusionResolver.csレシピを追加すると合体が増える。
D-05 形状変化転がし距離や保持時間でShapeを変える。ShapeMorphTracker.cs形状変化で性能が変わる。
D-06 属性床床エリア通過でPayloadに属性を付ける。FlavorFieldApplicator.cs一度使うと消える属性床が動く。
D担当の統合契約。 CollectionBufferは PayloadMutationSystem を呼ぶだけ。合体・形状変化の具体ルールはD担当モジュールに閉じる。

実装者E: ステージ崩落・雪崩

作業単位内容成果物完了条件
E-01 傾き制御敵撃破方向へFieldRootを一瞬傾ける。StageTiltController.cs左右どちらにも傾けられる。
E-02 雪崩フロー傾き方向へ物が流れる演出を出す。AvalancheFlow.cs物量が流れているように見える。
E-03 巻き添え判定雪崩範囲内の敵へ追加HitBatchを送る。AvalancheDamageZone.cs近くの敵が巻き添えを受ける。
E-04 落下判定物が場外へ出たとき回収/消去する。FallDetector.cs場外に残骸が溜まらない。
E-05 復帰処理傾いたFieldを元に戻す。StageTiltResetter.cs連続使用しても破綻しない。

実装者F: ボスステージギミック

作業単位内容成果物完了条件
F-01 ボスルール制限時間、ボスHP、クリア/失敗条件を作る。BossTimerRule.cs時間終了時に結果が出る。
F-02 重量床フィールド上の物量で床が沈む。FieldWeightSystem.cs物が多いと危険になる。
F-03 お宝保護落としてはいけない物を管理する。TreasureKeepRule.csお宝落下でペナルティが出る。
F-04 ボス攻撃傾き、落下、重みを絡めた簡易攻撃を作る。BossGimmickController.cs通常敵と違うプレイになる。

実装者G: UI・演出・フィードバック

作業単位内容成果物完了条件
G-01 HUD体力、保持数、容量、ゲージを表示。HudPresenter.cs / UI_HUD主要状態が常に見える。
G-02 敵ゲージ表示攻撃ゲージ、無効範囲、ダウン状態を表示。EnemyGaugeView.cs攻撃タイミングが読める。
G-03 ヒット表示Hit数、ダメージ、倍率を表示。HitPopupPresenter.cs大量ヒットの結果が気持ちよく見える。
G-04 カメラ演出大量解放、ダウン、崩落時に揺れ/ズーム。CameraFeedbackController.cs演出強度をInspectorで調整できる。
G-05 SE/VFX収集、合体、解放、命中、ナダレ開始の仮演出。FeedbackEventListener.csイベントに応じて反応する。

実装者H: 統合基盤・デバッグ・ビルド

作業単位内容成果物完了条件
H-01 Project Skeletonフォルダ、asmdef、基本namespace、空Sceneを作る。Assets/_Project構成全員が同じ構成で作業開始できる。
H-02 EventBusEventChannelまたは軽量EventBusを用意。EventBus.cs全担当が共通イベントを発行/購読できる。
H-03 PoolServiceCollectable/Projectile用プールを作る。PoolService.cs大量生成してもGCが増えにくい。
H-04 GameplayShell各SceneとPrefabを接続する。GameplayShell.unity統合用Sceneが起動する。
H-05 DebugOverlayスポーン、強制ダウン、ナダレ開始、メトリクス表示。DebugOverlay.unity検証が速くなる。
H-06 SmokeTest起動、収集、解放、敵ダウンの確認手順を作る。PrototypeSmokeTest.md統合後に最低限壊れていないと判断できる。

個人プロトの提出条件

  • 個人検証シーンが単体で再生できる。
  • READMEまたはScene内Textに操作方法が書かれている。
  • 統合に使うPrefabが1つ以上ある。
  • Inspectorで主要パラメータを調整できる。
  • Debug表示で内部値を確認できる。
  • 他担当の未完成機能に依存する場合、Mockで代替している。
  • 統合担当に渡す公開API、Event、Prefab名を明記している。
