02 Scene Structure

シーン構成

本プロトタイプでは、共有シーンを最小化し、各担当が自分の検証シーンで作業できるようにする。統合時はGameplayShellへStage、UI、DebugをAdditiveロードし、依存関係を明確にする。

シーン分割の結論

結論。 共有で直接編集するシーンは Boot と GameplayShell と Stage_Prototype_01 に限定する。各担当は Proto_担当名_機能名 シーンで実装し、統合はPrefabとScriptableObjectを通して行う。

Prefab契約

統合時に接続するPrefabには、必ずルートに契約用コンポーネントを置く。内部階層は担当者が変更してよいが、契約コンポーネントと公開プロパティは勝手に変更しない。

Prefabルート契約コンポーネント必須子オブジェクト公開API
PlayerPrototypePlayerControllerVisualRoot、ArmLeftArea、ArmRightArea、ReleasePoint、HealthRoot。Initialize(PlayerContext)、SetInput(IPlayerInput)、GetCollectionBuffer()。
Collectable_CommonCollectableEntityVisual、Collider、OptionalRigidbody。Collect(ICollector)、Despawn()、GetPayload()。
EnemyPrototypeEnemyControllerGaugeAnchor、BodyHitArea、WeakPoint、VfxAnchor。ApplyHitBatch(HitBatch)、SetDown(bool)、OnDefeated。
ReleaseEmitterReleaseEmitterSpawnMuzzle、TrajectoryPreview、ProjectilePoolAnchor。Emit(PayloadBatch, ReleaseContext)。
StageTiltGimmickStageTiltControllerTiltPivot、TiltTargets、AvalancheFlowArea。Tilt(TiltRequest)、ResetTilt()。

Scene所有権ルール

ルール内容目的
共有シーン編集の制限GameplayShellとStage_Prototype_01は統合担当が最終編集する。Unity Scene YAMLの競合を避ける。
個人作業はPrefab中心各担当は個人シーンでPrefabを更新し、統合へPrefabを渡す。担当範囲を明確化する。
ScriptableObjectは定義名固定参照切れを防ぐため、統合済み定義のリネームは統合担当の承認を必要とする。Scene/Preset破壊を防ぐ。
DebugSceneは自由個人検証用のDebugSceneは破壊的変更可。高速に試せる場所を維持する。

カメラ・UI・Debugの配置方針

  • CameraはGameplayShell側に置く。Stage側に置くとステージごとにCamera設定が散るため。
  • HUDはUI_HUDシーンに分離し、Gameplayのイベントを購読する。Gameplay側からUI GameObjectを直接参照しない。
  • DebugOverlayは常にAdditiveで足せるようにし、ビルド時に有効/無効を切り替える。
  • 個人検証シーンでは専用カメラを置いてよい。ただし統合用Prefabにカメラを内包しない。
