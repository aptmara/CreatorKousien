07 Integration Contracts

統合契約・品質管理

並列実装で最も危険なのは、各担当の成果物が個別には動くが、統合時に接続できない状態である。このページでは、Prefab、ScriptableObject、Event、Git運用、Debug、パフォーマンスの契約を定義する。

統合契約の基本

統合契約。 担当間の接続点は、C# interface、Event型、Prefabルートコンポーネント、ScriptableObject定義の4つに限定する。相手のScene階層や内部クラスへ直接依存しない。

Prefab契約詳細

Prefab必須コンポーネント必須Inspector項目禁止事項
PF_Player_PrototypePlayerController、PlayerMotor、PlayerCollector、ReleaseController、PlayerHealth。MoveSpeed、CollectRadius、BufferCapacity、ReleasePoint、Health。Cameraを内包しない。Stageへの直接参照を持たない。
PF_Collectable_CommonCollectableEntity、Collider。CollectableDefinition、CollectVfx、PoolKey。収集時にDestroyしない。Poolへ返す。
PF_ReleasedPayloadReleasedPayloadProjectile、Collider、Rigidbody。LifeTime、HitRadius、VisualRoot、PoolKey。敵HPを直接減らさない。HitBatchへ渡す。
PF_Enemy_PrototypeEnemyController、EnemyAttackGauge、BarrierController。EnemyDefinition、GaugeAnchor、BodyHitArea、WeakPointRoot。Playerを直接検索しない。攻撃対象はContextで受け取る。
PF_StageTiltGimmickStageTiltController、AvalancheFlow。TiltPivot、TiltAngle、TiltDuration、AvalancheZone。EnemyをFindで探さない。Eventで起動する。

Event契約

ルール内容理由
Event名は過去形PayloadReleasedEvent、EnemyDownStartedEventなど。命令ではなく事実通知として扱うため。
EventにGameObjectを入れすぎないID、位置、数値、Snapshotを優先する。購読側が相手内部に依存しないため。
戻り値を期待しない結果が必要な処理はinterfaceで直接呼ぶ。Event順序依存のバグを避けるため。
UIはEvent購読のみHUDはGameplayを直接操作しない。表示とルールを分離するため。
Debug Commandは別扱いDebugだけはCommandBusで強制操作可。検証効率を上げるため。

Git / Unity並列作業ルール

項目ルール理由
ブランチfeature/A-player-collection のように担当と機能を入れる。作業範囲を把握しやすくする。
Scene編集共有SceneはHまたは該当Sceneオーナーのみ編集。Unity Scene競合を避ける。
Prefab編集自分の担当Prefabは自由。共有Prefabのルート契約変更は禁止。統合破壊を防ぐ。
Meta file.metaを必ず管理対象に含める。参照切れを防ぐ。
PR単位機能1つ + 検証シーン + README更新。レビューしやすくする。
マージ条件コンパイルエラーなし、個人Scene起動、契約変更の記録。統合ブランチを壊さない。

リスクと対策

リスク原因対策
集める時間が作業になる収集中の判断がない。属性床、合体候補、敵ゲージ圧、バリア条件を入れる。
物量で処理落ちする全物体を物理演算している。収集中Payload化、Projectile上限、Pool、HitBatch集計。
何を狙えばいいか分からない敵ゲージ/バリア/DropZoneが見えない。HUDとGizmo風表示を強める。
合体が覚えゲーになるレシピを知らないと損をする。合体はボーナス扱い、候補UI、カテゴリベース判定。
統合時に壊れる内部実装へ直接依存している。interface、event、Prefab契約を守る。
ミニゲーム感が強い短いステージで単発結果だけを見る。常に物が動く、敵やフィールドが変化する、連鎖を入れる。
