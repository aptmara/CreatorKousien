05 Implementation Order

実装順序

実装順序は、個人プロト、統合、全体プロト調整の3段階に固定する。最初から全員で1つのシーンを触るのではなく、個人検証で手触りと仕様を固め、契約に沿って統合し、最後に体験として調整する。

Phase 0: 着手前の共通準備

個人プロトに入る前に、統合担当が最低限の土台を作る。ここを飛ばすと、各担当が違う型・命名・Scene構成で進み、統合時に破綻する。

順作業担当成果物完了条件
0-1Unityプロジェクト作成、フォルダ構成、asmdef作成。HAssets/_Project、asmdef。全員がCloneして開ける。
0-2Core契約定義の初版作成。H + A/B/CPayload、PayloadBatch、HitBatch、interface群。A/B/CがMockでコンパイルできる。
0-3Event型の初版作成。H + GCollectionChangedEventなど。Gが仮HUDで購読できる。
0-4個人検証シーンの空Scene作成。HProto_A〜H scene。各担当が自分のSceneだけ編集できる。
0-5最低限のPlaceholder素材準備。G/HCube、Sphere、EnemyDummy、UI font。全員が同じ仮素材を使える。

Phase 1: 個人プロト

目的

個人プロトでは、各カテゴリの「成立する/しない」を最短で確認する。コード品質は一定守るが、作り込みよりも、統合可能な形で動くことを優先する。

個人プロトの完了ゲート

ゲート確認内容失敗時の処理
G1: 単体起動担当SceneがエラーなしでPlayできる。統合禁止。コンパイルエラーを先に直す。
G2: Mock接続依存先が未完成でもMockで動く。依存を直接参照している箇所をinterfaceへ戻す。
G3: Inspector調整主要値をコード変更なしで調整できる。SerializeFieldまたはScriptableObjectへ出す。
G4: 成果物明示統合に渡すPrefab/Script/ScriptableObjectが分かる。READMEを更新する。
G5: 破綻条件メモ大量数、連続操作、Scene再生停止時の既知問題が記録されている。統合時のリスクとして登録する。

Phase 2: 統合

統合の原則

  • 統合はH担当が主導し、共有シーンの直接編集者を絞る。
  • 最初に見た目を合わせるのではなく、データの流れを合わせる。
  • 接続に失敗した場合、担当モジュールの内部を統合担当が勝手に改修しない。契約のズレを修正する。
  • 一度に全機能を入れない。収集→解放→敵ゲージ→ダウンの順に通す。

統合順序

順統合作業接続する担当確認内容完了条件
2-1GameplayShell起動HBootからGameplayShell、Stage、HUDがロードされる。空ステージでPlayできる。
2-2Player配置A/HPlayerがSpawnPointに出て移動する。Stage上を移動できる。
2-3Collectable配置D/HSpawnZoneから物が出る。物が一定数維持される。
2-4収集接続A/D/G物を拾い、BufferとHUDへ反映される。保持数が見える。
2-5解放接続A/B/G保持物を落とし、Projectileが出る。保持数が減り、落下演出が出る。
2-6敵接続B/C/GProjectileが敵に当たり、ゲージが減る。ゲージ0で敵がダウンする。
2-7本体ダメージB/C/Gダウン中にHPが減る。敵を倒せる。
2-8崩落接続C/E/G敵撃破でFieldが傾き、雪崩が起きる。近くの敵に巻き添えが入る。
2-9ナダレタイム接続B/C/D/G短時間大量ヒットでSuperAvalancheが始まる。通常時より物量が増える。
2-10クリア/失敗接続C/F/H/Gボス/体力/時間条件で結果が出る。1プレイが終わる。

統合時に削ってよいもの

削る候補削る条件残す代替
形状変化収集→解放のテンポを邪魔する場合。合体だけ残す、またはPayload性能変化だけ残す。
属性床配置調整が間に合わない場合。特定Collectableの属性だけ残す。
ボス重量床通常ループが未完成の場合。通常ステージの強敵として扱う。
複数バリア分かりづらい場合。1種類の無効範囲だけ残す。
複雑な腕操作操作慣れに時間がかかる場合。移動のみ + 自動収集範囲に戻す。

Phase 3: 全体プロト調整

調整の優先順位

優先項目調整対象見る指標
1収集の気持ちよさ収集範囲、吸い込み速度、保持Visual、SE。拾った瞬間の手応えがあるか。
2解放の結果感落下数、ヒット間隔、ダメージ表示、カメラ揺れ。大量に落とした差が分かるか。
3敵ゲージの読みやすさゲージ速度、無効範囲、ダウン表示。いつ攻撃すべきか理解できるか。
4スーパーナダレタイム発動条件、時間、物量倍率、演出。狙って発動したくなるか。
5判断の発生バリア、属性、合体、DropZone配置。ただ全回収するだけになっていないか。
6負荷Projectile数、Pool数、VFX数、UI更新頻度。処理落ちで爽快感を損なわないか。

プレイテスト観点

質問確認したいこと改善方向
何をすればいいか分かったか収集→落とすの理解。導線、UI、最初の敵配置を修正。
集める時間は退屈ではないか収集中の変化や判断。合体候補、属性床、敵ゲージ圧を強める。
落とした結果は気持ちいいか蓄積×解放の成立。ヒット演出、数値、SE、敵リアクションを強める。
何を上手くなればよいか分かるか攻略性。バリア条件、ゲージ無効範囲、DropZoneを明確化。
もう一度遊ぶ理由があるか拡張余地。ステージ変化、物の組み合わせ、敵配置を増やす。

プロトタイプ完成判定

完成判定。 60〜90秒の1プレイで、プレイヤーが物を集め、敵ゲージを見ながら大量に落とし、敵をダウンさせ、スーパーナダレまたは崩落で大きな結果を出せる状態を完成とする。見た目の完成度ではなく、企画の核である「蓄積×解放」が体験として成立していることを基準にする。
