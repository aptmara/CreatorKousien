<RULE>
ユーザーから「diffからIssueとPRを作成して」と依頼された場合、Agentは以下の【対話型ワークフロー】を必ずステップ・バイ・ステップで実行し、各ステップでユーザーの確認を求めながら進行すること。決して独断で全ステップを一度に完了させないこと。

### 前提条件: テンプレートの厳守
このリポジトリには厳格な規約とテンプレートが存在する。これらから絶対に逸脱してはならない。
1. **Issueテンプレート**: `.github/ISSUE_TEMPLATE/` 内のYAMLファイル (`01_task.yml`, `02_bug.yml` 等)
2. **PRテンプレート**: `.github/PULL_REQUEST_TEMPLATE.md`
3. **命名規則**: `docs/CONTRIBUTING.md`
   - ブランチ名: `<type>/#<issue番号>-<内容>` (例: `feature/#12-player-move`)
   - PRタイトル: `[#<issue番号>] <概要>`

---

### 【対話型ワークフロー】

#### Step 1: 変更内容とテンプレートの解析
1. `git diff` または `git status` を実行し、変更内容を把握する。
2. `.github/ISSUE_TEMPLATE/` 内の該当するテンプレートと、`docs/CONTRIBUTING.md` を読み込む。
3. **Agentのアクション**: 変更内容に基づき、テンプレートの項目（概要、背景、完了条件など）を埋めた Issue のタイトルと本文案を作成し、ユーザーに提示して**承認を求める**。

#### Step 2: Issue の作成
1. ユーザーから Issue 案の承認を得たら、一時ファイル (`issue_tmp.md`) を作成し、`gh issue create` コマンドで Issue を発行する。
2. **Agentのアクション**: 発行された Issue 番号と URL をユーザーに報告し、次のステップ（ブランチ作成）に進んでよいか確認する。

#### Step 3: ブランチの作成とコミット
1. 取得した Issue 番号をもとに、`docs/CONTRIBUTING.md` に従ったブランチ名（`<type>/#<issue番号>-<内容>`）を決定する。
2. `git checkout -b <ブランチ名>` でブランチを作成。
3. `git add` および `git commit` を実行（コミットメッセージも規約に従う）。
4. `git push -u origin <ブランチ名>` でリモートにプッシュ。
5. **Agentのアクション**: プッシュ完了を報告し、PR作成に進むための準備を行う。

#### Step 4: PR の作成案提示と発行
1. `.github/PULL_REQUEST_TEMPLATE.md` の内容を読み込み、PR のタイトル（`[#<issue番号>] <概要>`）と本文案を作成する。
   - ※必ず `Closes #<issue番号>` を含めること。
   - ※セルフチェックリストの `[ ]` を `[x]` に変更すること。
2. **Agentのアクション**: PR案をユーザーに提示し、**承認を求める**。
3. 承認を得たら、`gh pr create` コマンドで PR を発行する。
4. 一時ファイル等のクリーンアップを行い、最終的な PR URL をユーザーに提示して完了とする。

---
※注意: Windows環境で `gh` コマンドを実行する場合、エイリアスや構文エラーを避けるため `cmd.exe /c 'gh ...'` の形式を使用すること。
</RULE>
